# ICP, Buyer, and JTBD Map

**Date:** 2026-07-31

## Primary ICP (recommended)

**AI-native knowledge teams (engineering, product, research) of 20–200 people** that already run coding/research agents and hold sensitive proprietary context.

| Role | Who |
|---|---|
| Primary user | Staff+/tech lead, research lead, or AI platform engineer |
| Economic buyer | Eng Manager, Head of AI/Platform, or CTO |
| Technical buyer | Platform/security engineer |
| Gatekeeper | Security/compliance (esp. if customer data in context) |
| Admin | Same as technical buyer initially |
| Blocker | “We already have Slack+Notion+Linear+Cursor” |
| Current alternative | Ad-hoc agent chats + docs + tickets; maybe an MCP gateway |
| Switching trigger | Audit scare, agent incident, customer-data policy, founder design-partner offer |
| Budget source | AI tooling / productivity / security line items |
| Procurement | Bottom-up tool trial → security review → team license |
| Proof to buy | One governed run producing accepted artifact with evidence in <1 day |

## Secondary ICPs

1. Boutique consulting / research firms (evidence-heavy deliverables).
2. Regulated knowledge orgs needing managed-private deploy (longer cycle).
3. Personal power users (PLG top-of-funnel, weaker ACV).

## JTBD (primary)

> When I delegate work to an agent over my team’s private context, I want a bounded, approvable run that produces an evidence-linked artifact I can trust—so I can ship decisions without reconstructing context or gambling on silent side effects.
